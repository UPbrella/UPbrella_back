# 격리된 홈 개발 환경

이 폴더는 애플리케이션 산출물과 별도 개발 DB·업로드 볼륨을 사용하는 구성입니다. 실제 접속키, DB 비밀번호, 운영 덤프·암호화 키, 서버 백업과 빌드 산출물은 포함하지 않습니다. `.gitignore`로도 제외합니다.

## 구성

- MySQL 8, Spring Boot(home-dev), Nginx. CPU/메모리와 로그 용량에 상한을 두고 서비스는 localhost 포트에 바인딩합니다.
- `initialize-secrets.py`는 최초에만 권한 600의 무작위 secret.env를 만들고 기존 파일을 덮어쓰지 않습니다.
- home-dev에서만 접속키 기반 가상 사용자/운영진 로그인을 켤 수 있습니다. 키와 프로필이 모두 맞아야 하며 운영 프로필에는 이 컨트롤러가 없습니다. 빈 DB에서만 가상 지점을 초기화합니다.
- Slack과 실제 OAuth는 home-dev에서 비활성입니다. 개발 세션 쿠키는 이름과 경로를 분리합니다.

## 배포 준비

Java 17과 프런트 저장소에서 지정한 Node 22/pnpm 버전을 사용합니다. 백엔드 jar를 이 폴더의 app.jar로 복사하고 프런트 빌드 결과를 frontend/에 복사합니다. 프런트 보조 빌드 스크립트를 쓰려면 `UPBRELLA_WORKSPACE`를 backend/와 frontend/가 있는 상위 폴더로 지정합니다. 지도 클라이언트 키는 프런트의 Git 제외 .env.home-dev.local에 설정합니다.

개발 서버에서 `python3 initialize-secrets.py`와 `docker compose up -d --build`로 시작합니다. 고정 HTTPS 경로가 필요하면 `install-system.sh`를 서버에서 직접 실행합니다. 이 설치기는 Nginx를 검사·백업하고 개발 경로를 추가합니다. Cove의 네이티브 MySQL/Redis 중지 단계는 사용 여부 감사 조건을 만족할 때만 수행하며 데이터 파일은 남깁니다. 이 PR 준비 과정에서는 스크립트를 실행해 서버 서비스를 변경하지 않았습니다.

## 운영 데이터 복사

`clone-production.py`는 홈서버의 기존 스냅샷을 새로운 개발 스키마에 복원하고 원래 컬럼의 행 수/해시를 검증합니다. 운영 DB를 대상으로 쓰기 작업을 하지 않습니다. `activate-clone.py`는 검증한 복사본으로 개발 API만 전환하고 이전 설정과 롤백 경로를 보존합니다. 실행 전 복사본과 목적지를 운영자가 확인해야 합니다. 회원 정보를 포함하는 덤프·키·검증 원문을 저장소에 추가하지 않습니다.

개발용 데이터 변형 검증 스크립트나 실제 개발 데이터·배너 DB 레코드는 PR에 포함하지 않았습니다. 가상 우산은 기존 생성 요청 팩토리를 사용하므로 상태 모델 PR #521과 함께 적용할 수 있습니다.
